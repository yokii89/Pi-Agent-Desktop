A session monitor you can keep in view, a commit dialog, and background processes you can finally look inside.

## Session monitor

- **A monitor card holds the right edge.** Close the context sidebar and the card takes its place beside the conversation. The transcript keeps exactly the same width open or closed, and the card slides in and out with the sidebar's own motion.
- **This round at a glance.** The card opens with this round's summary and when it last changed, then lists the environment: your project's uncommitted changes (+N −M across the whole working tree, not just this round), the working folder, the branch, and the commit / push state.
- **Skills and MCP by actual use.** These rows count what this session really called — each skill with its command and file-read counts, each MCP server with per-tool counts on hover — instead of what merely exists. Long lists fold into a single "N more" row.
- **Every row is a shortcut.** Changes open the review panel with all changed files, the working folder opens in Explorer, and process rows open their details.

## Commit or push

- **Commit without leaving the conversation.** The card's "Commit or push" row opens a centered dialog: the current branch (read-only), a message field that must be filled, and a switch to include unstaged changes — with the diff stat for the set you are about to commit. Push, commit-and-push and commit sit side by side, and Ctrl / Cmd + Enter commits.

## Background processes

- **A Background processes tab.** Open it from the right sidebar, or click a process row on the monitor card or the floating card — the process is selected for you. The list tops the tab, and the selected process shows its details below: the bash command that started it, its child process tree, TCP endpoints and memory.
- **States are shown as they are.** Running, stopped and exited are told apart — a process that outlived its session and has no exit code is never dressed up as failed. Finished entries can be dismissed from their details so long sessions stay tidy.
- **Stays current, stops when done.** A running process's details refresh every three seconds; once it is gone, refreshing stops. If stopping fails, the stop button stays on the row so you can try again.

## Sidebar and layout

- **A new session shows up the moment you send.** Its row enters the sidebar immediately, and the project or task group opens to reveal it.
- **Sidebar resizing sticks.** Dragging the sidebar wider no longer gets overridden afterwards.
- **One column width.** The transcript and the floating input bar now share the same column, and tool, thinking and source rows light up in your accent colour on hover.

## Fixes

- A command that is backgrounded right away (`npm run dev &`) is no longer missed by process tracking.
- Re-checking processes after a failed enumeration no longer reports them as exited, and batch stops verify the PID has not been reused before terminating.

## 简体中文

一张随时看得见的会话监控卡、一个提交浮窗，以及能翻开看的后台进程。

### 会话监控卡

- **右缘常驻一张监控卡。** 收起上下文侧栏后，卡片接管侧栏让出的位置，出现在对话右侧。无论侧栏开合，对话列的宽度都保持不变，卡片跟着侧栏的动效滑入滑出。
- **本轮情况一眼看完。** 卡片先给出这一轮的摘要和最后更新时间，再依次列出环境：项目全部未提交改动（+N −M，整份工作区而不只是本轮）、工作目录、当前分支，以及提交 / 推送状态。
- **技能与 MCP 看实际调用。** 这两行统计的是本次会话真正调了什么，而不是有什么可用：每个技能带上命令与读取文件的次数，每个 MCP 服务器按工具给出次数（悬浮可见），过长的清单收成一行「还有 N 项」。
- **每一行都能点。** 改动行打开审阅面板并列出全部改动文件，工作目录行在资源管理器打开，进程行打开进程详情。

### 提交或推送

- **不离开对话就能提交。** 点卡片上的「提交或推送」打开居中浮窗：当前分支（只读）、必填的提交说明，以及「包含未暂存变更」开关，并给出所选范围的增删统计。推送、提交并推送、提交三个动作并排，Ctrl / Cmd + Enter 等同提交。

### 后台进程

- **新的「后台进程」页签。** 从右侧栏打开，或直接点监控卡 / 中央浮卡上的进程行——打开时已替你选中该进程。上方是进程列表，下方是选中项的详情：启动它的 bash 命令、子进程树、TCP 端点与内存。
- **状态照实显示。** 运行中、已停止、已退出分开呈现——会话结束还在跑、没有退出码的进程不会被标成「失败」。已结束的条目可以在详情里忽略，长会话不会越积越多。
- **该刷就刷、该停就停。** 运行中的进程每三秒刷新一次详情，进程消失后停止刷新；停止失败时行上仍保留停止按钮，可以重试。

### 侧栏与布局

- **新会话发出即入列。** 发送的瞬间侧栏就出现它的行，所属项目 / 任务分区自动展开。
- **侧栏加宽不再被压回。** 拖动加宽后不会再被上一次的宽度覆盖。
- **同一列宽。** 对话流与悬浮输入栏现在共用同一列；工具、思考与来源行悬浮时改为主题色文字。

### 修复

- 立即转入后台的命令（如 `npm run dev &`）不再漏登记进程。
- 进程复核失败时不再误标「已退出」；批量结束前会校验 PID 是否被复用。
